About

I'm a backend and platform engineer. Most of my work sits underneath the product: the database schema, the migration that has to run without anyone noticing, and the infrastructure that keeps services talking to each other.

For the last while I've been leading the design and migration of a multi-tenant PostgreSQL platform that replaces a legacy monolithic database. That meant composite foreign keys so tenant scoping is enforced by the schema instead of by application code remembering to filter, row-level security policies on top of that, and a dual-write expand-contract rollout (Flyway-versioned) so the cutover happened with zero downtime.

I also own the change-management workflow for our production and staging releases, which means coordinating across QA, database and cloud teams and making sure nothing ships that we can't roll back.

  • Databases: PostgreSQL, schema design, row-level security, migrations, CDC pipelines
  • Cloud: AWS Lambda, API Gateway, EKS, ECS, ECR, S3, RDS, KMS, Cognito
  • Languages: Python, SQL, Java, JavaScript
  • Backend: FastAPI, Flask, REST APIs, event-driven architecture

I care about systems that stay clean as they get more complicated, and migrations that don't break things on the way. Happy to talk to anyone working on distributed systems, healthcare tech or database architecture.
